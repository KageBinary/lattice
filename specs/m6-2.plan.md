## Carry-overs from review

- **To T3 (from T1):** E0420 is already raised at a `force:` site that names an observer
  (compile.rs); keep it, and use the same code at the `observe` callee. Unused observers
  warn W0316 with "nothing observes it … not implemented yet"; once the `observe` site
  records use, keep W0316 for the truly unused and drop the "not implemented yet" note.
  `UserLaw::new` refuses `BodyObserver` (a real `assert!`), so `LawObserver` needs its own
  evaluator. Observer laws are not lowered in the pipeline yet; E0413 must apply when T3
  lowers them at the `observe` site.
- **To T3 (from T2):** the CLI (`project.rs`) does not print `RunOutcome::observer_faults`
  as rendered `E0951` diagnostics; they reach only the artifact's warnings.
  `ObserveContext::domain` returns `None` for a domain outside the contract's `reads`, so
  the generated `LawObserver` contract must list its set.
- **To T6 (from T2):** the viewer calls `observe()` once per frame (its own cadence, not
  the model's `every`) and never shows E0951. Document this. A non-finite observer row
  halts the run (spec G7, kept after two reviewers questioned it); `catch_unwind` isolates
  panics only, not loops, stack overflow or aborts.
- **To T4 (from T2 round 4):** an observer publishing the same declared row twice in one
  call passes every check (refuse it as a contract breach); `Observer::contract()` is called
  outside `catch_unwind` in the fault-recording and row-validation paths of
  `lattice-runtime/src/lib.rs`, so a panicking `contract()` takes the run down (cache each
  observer's contract at `add_observer` and never call it again, or guard every call).
- **To T5 (from T3):** law observers land in `Compiled.observers` and are not attached
  automatically; `compile_file` must call `Simulation::add_observers(compiled.observers)`
  (the CLI, viewer, fixture tests and validation already do).
- **To T6 (from T3):** the viewer shows a law observer with `every` only at frames on its
  cadence; the t = 0 sample is not checked for non-finite values (as for every row);
  `min`/`max` propagate NaN rather than skip it; E0201 (repeated row) and E0405
  (non-positive `every`) were added at the `observe` site beyond the spec.
- **To T6 (from T3 review):** document that a law observer skips the run's forced final
  sample when it is off its cadence (G3); that `observe sum(atoms)` (a reduction over a
  non-call) is now E0202 (O1(a)); that the spec's own §25.1 `observe total_species` draws
  W0320 because no domain publishes that name; and correct spec §4.3's dictated
  `LawObserver` limitation text (min/max ties are order-independent; sum/mean are not).
- **To T5 (from T3 round 3):** the public `LawObserver::new` accepts `Some(0.0)` or
  `Some(NaN)` as the interval and then silently samples every step. The compiler refuses
  this with E0405, but SDK users bypass the compiler, so refuse it (or document it) in the
  SDK surface.
- **To T6 (from T3 round 3):** E0201 "observed twice" (compile.rs, `lower_observers`) tells
  the user to change the cadence even when only the law's parameters differ (the row name
  `SET.LAW.RED` leaves the parameters out); fix the help text and document the limitation.
  The doc comment on `LawObserver::due` says "the sample nearest the instant", but the code
  takes the first sample at or past it (to within half a step).
- **To T6 (from T5 review):** the validation case count is stale (77 in `README.md:110`,
  `docs/backends.md:448` and `docs/development.md:56`; recount from `lattice validate`
  after T5 merges). `plugin_vacf_ideal_gas` shells out to `cargo run --release` on
  `plugins/vacf` through the compile-time `CARGO_MANIFEST_DIR`: `lattice validate` needs
  cargo and a source checkout, otherwise that case fails as unmeasured. Its first run also
  does a second release build of the engine into its own target dir. Document all of this
  in docs/plugins.md and docs/development.md.
