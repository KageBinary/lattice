# M6.2 — Observers a user can write

Governing specification: `docs/spec/project-lattice-spec-v0.1.md`, P1, P8, FR-001, FR-015,
NFR-001, NFR-004, §16.3 (the Observer tier), the IR table's Observer row (`:287`), and M6's
exit condition (`:791`, *"external user can author custom law and observer"*).
Roadmap row: `docs/roadmap.md:695`.

## 1. Summary

M6.1 made the first half of M6's exit condition true: a user can write a force, a potential
or a rate law. The second half, *"and observer"*, has no implementation. `observer` is a
reserved law kind that fails with `E0900` ("arrives in M6.2",
`crates/lattice-compiler/src/laws.rs:117`, `:394-404`). The survey for this spec also showed
that today's observer machinery has less in it than its syntax suggests:

- `observe <target> every <t>;` compiles to `ObserverSpec { target, interval }`
  (`crates/lattice-ir/src/model.rs:223`), but nothing resolves or uses the target.
  `RunConfig::from_model` (`crates/lattice-runtime/src/lib.rs:80-95`) takes the smallest
  interval of all observers as the single sample cadence, and every domain's whole
  `observe` set is recorded at that cadence. The examples' targets are a mix of domain
  names (`atoms`, `q`) and species (`A`, `B`). A misspelt target goes unnoticed.
- Each domain's observations are hand-written. There is no shared reduction and no
  registration point (`Domain::observe`, `crates/lattice-ir/src/contract.rs:456`). The
  compiler instantiates every domain itself, so code outside the engine cannot add an
  observer to a run.
- The run artifact's timeline keeps `(name, value)` and drops the unit and the kind
  (`crates/lattice-observe/src/artifact.rs:143`).

M6.2 adds three things:

1. `observer` laws in `.lattice`: a per-particle expression, reduced over a particle set by
   `sum`, `mean`, `min` or `max` at the observer's own cadence.
2. A Rust `Observer` trait with a declared contract. It gets read-only access to domain
   state, keeps its own state between samples, and is attached to a compiled simulation
   from outside the engine. The engine's own law observers go through the same trait, so
   it is not an interface that only the example uses.
3. A `lattice-sdk` crate that re-exports a versioned public surface, plus an example
   plugin crate outside the workspace that builds against it. That example plugin is
   FR-015's acceptance test.

## 2. Goals and non-goals

Goals:
- G1. `observer NAME(a: particle) -> UNIT { … }` type-checks and lowers like a body law.
  It may read `a.position`, `a.velocity`, `a.mass` and `a.charge`, plus `param`s and
  `let`s. It may not read concentrations or temperature, because it has no chemistry
  context. It returns a scalar quantity whose dimension is checked against the declared
  unit.
- G2. `observe REDUCTION(LAW(SET)) [every T];` evaluates the law once per particle of the
  particle domain `SET` and reduces the values in index order. `REDUCTION` is one of `sum`,
  `mean`, `min` or `max`. The recorded row is named `SET.LAW.REDUCTION`, carries the law's
  unit (unchanged by any of the four reductions), and has kind `Metric`. A user observer is
  never an `Invariant`, because the engine cannot know whether it is conserved.
- G3. Each user observer is evaluated only at samples where its own `every` is due (the
  existing half-step rule, `lib.rs:535-547`), not at the global minimum cadence. The
  timeline can be ragged because `TimelineSample` is a list of named pairs.
- G4. A plain `observe TARGET` is resolved. TARGET must be a domain instance, a species, or
  a published observation name. Otherwise the compiler emits warning `W0320`, "observe
  target names nothing", with a "did you mean" suggestion. The plain form keeps its present
  meaning: it sets a cadence and filters nothing (see O2).
- G5. `trait Observer` with an `ObserverContract` (P8: units, reads, side effects, backend,
  differentiability, plus P1's honest limitations). `ContractAudit` refuses an empty
  contract. `Simulation::add_observer` attaches one to a compiled simulation. Observers
  run after domains publish their rows, in attachment order, with `&` access to domains.
  An observer that panics is disabled. The run continues and records diagnostic `E0951`
  (NFR-004).
- G6. `lattice-sdk` is a facade crate. It re-exports `Observer`, the contract types,
  `ObserveContext`, `Observations`, `Curve`, read-only domain views (`ParticleView`), and
  `compile`/`Simulation`. It also exposes `SDK_VERSION`. `plugins/vacf/` is a standalone
  crate, not a workspace member. It implements a velocity-autocorrelation observer and
  builds and runs with no engine source changed.
- G7. The artifact records each series' unit and kind once, in a `series` table. The
  schema version goes up. A non-finite user-observer value halts the run like any other
  row, and `E0950` explains it by tracing the observer's program against the sampled state.
  That state is the observer's own input, so no replay is needed.

Non-goals:
- Pair observers (sums over neighbour pairs, such as coordination numbers). They need the
  neighbour list and the cutoff semantics of pair laws. This is the obvious next step and
  is deferred.
- Observer laws over grids, wavefunctions or rigid bodies. Only the particle domain has a
  law input layout today. A grid layout belongs with M6.3's WGSL work, which has to define
  one anyway.
- Dynamic loading (`dylib`/`cdylib`) or a stable ABI. Spec §23 calls the plugin ABI a risk
  and prescribes *"unstable internal ABI until mature"*. A plugin is a Rust crate that links
  the SDK and is compiled with the engine version it names.
- Filtering the built-in observations by target, or a `--only` flag. See O2.
- Parallel reductions. Observer evaluation stays sequential and in index order, which is
  the standing policy (`crates/lattice-cpu/src/exec.rs:19-23`), so thread count cannot
  change a reported value.
- CSV export, writing the ledger into the artifact, and removing the per-sample `format!`
  in the built-in domains' `observe`. All three surfaced in the survey and are logged in
  §6 rather than built here.
- `histogram` as a reduction. It produces a curve, not a scalar, and how to accumulate
  across samples (latest sample or running) is a design question of its own. The VACF
  plugin shows how a plugin publishes a curve, so the SDK path is covered.

## 4. Design

### 4.1 The law (G1)

```
observer kinetic_x(a: particle) -> joule {
  return 0.5 * a.mass * a.velocity.x * a.velocity.x;
}

observer right_half(a: particle) -> 1 {
  param x0: meter = 0 meter;
  return if a.position.x > x0 { 1 } else { 0 };
}
```

- `LawKind::Observer` is added. `parse` accepts `observer`, and `PLANNED_KINDS` becomes
  empty. `E0900`'s fixture is deleted with its test, and its row in language.md's "Not
  implemented yet" table goes too.
- The header takes exactly one `particle` parameter. A second one is `E0416`, "observer
  laws take one particle; pair observers are not implemented". This error is specific
  so that a user is not told something vaguer.
- The return type must be a scalar. A vec2 return is `E0417`, with a note telling the user
  to observe each component separately.
- `c(…)`, `temperature` and `arrhenius` in an observer are `E0418`, "observer laws read
  particles only".
- Lowering produces `UserLawKind::BodyObserver` with the body input layout and one output.
  No derivative is taken. `E0413`'s register limit applies unchanged.

### 4.2 The use site (G2, G3)

```
observe sum(kinetic_x(atoms)) every 0.1 picosecond;
observe mean(right_half(atoms, x0 = 2 nanometer));
```

- `lower_observers` recognises `CALL(CALL(LAW, SET, named args…))`, where the outer callee
  is a reduction name and the inner callee is an `observer` law. Binding named arguments
  to parameter slots reuses `user_force::bind`'s logic (`user_force.rs:53-131`), moved
  into a shared helper rather than copied.
- Errors:
  - `E0419`: the reduction is not one of `sum|mean|min|max`.
  - `E0420`: the inner callee is a law of the wrong kind, for example a `force`.
  - `E0421`: `SET` is not a particle domain.
- `ObserverSpec` gains `law: Option<ObserverLawUse>`, holding the program, the parameter
  values, the domain name, the reduction and the row name. The plain form keeps
  `law: None`.
- Reductions run in particle index order. `sum` is a left fold starting at `+0.0`. `mean`
  is that sum divided by the count. `min` and `max` use the sign rule M6.1d gave the
  interpreters for equal operands. On an empty set, `sum` is `0`, and `mean`, `min` and
  `max` are NaN. NaN is the honest answer there, because an empty `mean` has no value.
  A run halts on a NaN row, though, so the compiler warns (`W0321`) when the set can start
  empty. The halt itself is the documented runtime behaviour.
- Evaluation uses `eval_batch` over `LANES` particles, then reduces in gather order. The
  result is bit-identical to a scalar loop, and a test checks that.
- Each law observer keeps a `next_due` time. `run()` asks each one whether it is due at a
  sample instant, using the existing half-step rule. The global sample cadence remains the
  minimum interval, as today, so a law observer is never due between samples.

### 4.3 The trait (G5)

In `lattice-ir`, a new `observer.rs`. It goes there rather than in `lattice-runtime` because
the particle crate implements it and must not depend on the runtime:

```rust
pub trait Observer: Send {
    fn contract(&self) -> &ObserverContract;
    /// Called at every sample after all domains have published. `ctx.time()` and
    /// `ctx.step()` say when. Read-only on the simulation; mutable on itself.
    fn observe(&mut self, ctx: &ObserveContext<'_>, out: &mut Observations);
    /// Function-valued results, as `Domain::curves`. Default: none.
    fn curves(&self) -> Vec<Curve> { Vec::new() }
    /// Whether this sample instant is one this observer wants. Default: every sample.
    fn due(&mut self, time: f64, dt: f64) -> bool { true }
}

pub struct ObserverContract {
    pub name: Cow<'static, str>,
    pub summary: Cow<'static, str>,
    pub reads: Vec<Cow<'static, str>>,          // domain instance names
    pub outputs: Vec<(Cow<'static, str>, Unit)>, // row names and units; curves listed too
    pub side_effects: SideEffects,               // None | WritesFiles(paths) | Other(text)
    pub limitations: Vec<Cow<'static, str>>,     // P1: what it does not measure
    pub deterministic: bool,
    pub backends: Backends,                      // CPU only for now
    pub differentiable: bool,
}

pub struct ObserveContext<'a> { /* time, step, &[(&str, &dyn Domain)], &Observations */ }
impl ObserveContext<'_> {
    pub fn observations(&self) -> &Observations;           // rows the domains just published
    pub fn domain<T: 'static>(&self, name: &str) -> Option<&T>;
}
```

- `Domain` gains `fn as_any(&self) -> &dyn Any`, implemented by every domain. That is the
  whole downcast mechanism.
- The SDK's `ParticleView` wraps `&ParticleDomain` and exposes read-only slices (positions,
  velocities, masses, charges) and nothing that mutates. Plugins use this view, not
  `ParticleStore`, so the store can change without breaking them.
- `ObserverContract::audit` reports a gap when `summary`, `reads`, `outputs` or
  `limitations` is empty, or when a name in `reads` does not exist in the model.
  `Simulation::add_observer` runs the audit and returns `Err` on a gap. This is stronger
  than the solver contract's test-time audit, and that is deliberate: a plugin has no
  validation suite of ours to fail.
- Each observer call is wrapped in `catch_unwind(AssertUnwindSafe(…))`. Because of the `&`
  access, a panic cannot have mutated the simulation. Unwind safety is about the
  observer's own state, and that observer is then disabled. The run records `E0951`
  ("observer `vacf` panicked at step N and was disabled: <message>") into the stop
  report's diagnostics, and the run continues.
- Law observers (§4.2) are a `LawObserver: Observer` in the particle crate. Its contract is
  generated: its `reads` is the set, its `outputs` is the row and unit, and its
  `limitations` is `["sampled at observation instants only", "sum and mean depend on
  particle index order in their last bits: floating-point addition is not associative, so
  relabelling the particles can change them", …]`. (The first draft of this text said the
  *min/max ties* were order-dependent, which is backwards: min and max pick equal values
  by sign, so they do not depend on order. It is `sum` and `mean` that do. The code's
  contract also says the row is a metric and that an empty set's `mean`, `min` and `max` are
  NaN.)
- Determinism: observers run sequentially in attachment order. Law observers attach first,
  in source order. The CPU pool never runs them, so the thread-count identity case extends
  to their rows.
- **As built, where it differs from the sketch above.** `Domain::as_any` already existed
  (`Domain: DomainType`, with a blanket `impl<T: Any> DomainType for T`), so no domain
  needed a line. `outputs` holds `(Cow<str>, Cow<str>)`, because the workspace has no
  `Unit` type and an observation's unit is a string. `ObserveContext` borrows the
  simulation's `&[Box<dyn Domain>]` rather than a list of pairs, so a sample allocates
  nothing. `audit` takes the model's domain names, and also refuses an empty `name`, no
  backend, and (in `add_observer`) an output another observer declares or a domain
  already publishes. `Observer` has a fourth method, `explain_non_finite` (G7).

### 4.4 The SDK and the example plugin (G6)

`crates/lattice-sdk` contains only re-exports, `ParticleView`, and:

```rust
pub const SDK_VERSION: (u32, u32) = (0, 1);
pub fn compile_file(path: &Path) -> Result<Simulation, Vec<Diagnostic>>;
```

`plugins/vacf/` has its own `Cargo.toml` with a path dependency on `lattice-sdk` and its
own `[workspace]`, so it is outside the engine's workspace. It contains a library with
`Vacf: Observer` and a binary that compiles a model, attaches `Vacf`, runs it, and prints
the curve.

```
C(τ) = ⟨ v(t)·v(t+τ) ⟩ / ⟨ v(t)·v(t) ⟩
```

It is computed from velocity snapshots kept in a fixed ring of length `L`, allocated in
`new`, with time origins at every sample. It publishes `C(τ)` as a curve and `C(1 lag)` as
a row. Its contract declares `limitations: ["lags are multiples of the sample interval",
"origins overlap; no error bar"]`. FR-015 says *"Example plugin builds without modifying
engine source"*, and `plugins/vacf` building and running against an unmodified engine is
the test of that.

### 4.5 Artifact (G7)

`canonical_json` gains a `series` object, `{name: {unit, kind}}`, written once in name
order, and `ARTIFACT_SCHEMA` is incremented. Every existing content hash changes once.
`docs` records that, and no hash is pinned in tests other than the artifact's own
round-trip test. The builder confirms that by grep before relying on it.

## 5. Alternatives considered

- **Putting the reduction in the law** (`observer ke(a) -> joule reduce sum {…}`). Then
  the same per-particle quantity cannot be both summed and maxed without writing it twice.
  Rejected in favour of a reduction at the use site.
- **A new `measure` statement.** The existing `observe EXPR` grammar already parses the
  call form, and a second statement would make users choose between two near-synonyms.
  Rejected.
- **Plugins through the `Domain` trait.** A plugin domain would need the compiler to know
  about it, and it gets `&mut` state, which is exactly what §16.3's Observer tier forbids.
  Rejected.
- **Exposing `ParticleStore` directly** instead of a view. That is less code now, but every
  store refactor would break plugins. Rejected because of §23's ABI risk.
- **Giving observers the CPU pool.** Ruled out by the reduction policy, and a sampled
  observer is not the hot loop.

## 6. Risks and open questions

- **O1 (decided 2026-11-09: (a)): use-site syntax.** (a) `observe sum(ke(atoms)) every T;`, recommended,
  because the parser already accepts it and nothing new is reserved. (b)
  `observe sum ke over atoms every T;`, which reads better but adds two keywords and a
  grammar rule. (c) The reduction declared in the law (§5, rejected there, listed for
  completeness). **Recommend (a).**
- **O2 (decided 2026-11-09: (a)): what the plain `observe TARGET` means.** (a) Resolve and warn (`W0320`),
  keep recording everything, and change no existing output. Recommended for this stage,
  because it makes misspellings visible without changing any artifact other than through
  the §4.5 schema bump. (b) Make the plain form filter, so only the named domain's rows are
  recorded. This is more honest about the syntax, but it changes what every example
  records and needs a decision about species targets. It could be its own small stage.
  **Recommend (a), and record (b) in the roadmap's handoff.**
- **O3 (decided 2026-11-09: (a)): the plugin location.** (a) `plugins/vacf/` inside this repo but outside the
  workspace, built by a validation case and by `development.md`'s check script.
  Recommended: it proves the claim on every run. (b) A separate repository, which is more
  convincing about "external" but is checked by nothing. **Recommend (a).**
- **R1.** `catch_unwind` does not catch an abort, such as a panic in a destructor during
  unwind or `panic = "abort"` in the profile. The workspace profile has to stay `unwind`,
  and the builder checks `Cargo.toml`. The docs will say that NFR-004 holds for
  panics, not aborts.
- **R2.** `as_any` makes it possible to downcast to a concrete domain type, so a plugin
  that bypasses `ParticleView` couples itself to internals. The SDK docs say the view is
  the supported surface, and §23 already says the internal ABI is unstable.
- **R3.** VACF under a Langevin thermostat decays as `exp(−γτ)` only for free particles. In
  a dense LJ fluid it does not. The validation case uses an ideal (force-free) gas, so the
  analytic answer is exact up to the integrator's discretization of the O-step, which is
  exact for BAOAB's OU update.
- **Found by the survey and not fixed here:** the ledger is missing from the artifact
  (`crates/lattice-cli/src/project.rs:290` claims otherwise, and T6 corrects that comment);
  domains `format!` names on every sample (NFR-001); and contract audit coverage is partial
  (the validation case covers particle, heat and rigid, the CLI covers particle and heat).
  T6 adds all three to the roadmap handoff.

## 7. Validation

- **Law checking:** `observer` accepted. Fixtures for `E0416` through `E0421`, and for
  `W0320` and `W0321`, under `tests/invalid/` (warnings get a CLI warning test). The `E0900`
  fixture is removed.
- **Reduction bit-identity:** for 1, 7, 8, 9 and 1,000 particles, the batched evaluation
  plus index-order reduction equals a scalar reference loop under `to_bits()`, for each of
  the four reductions.
- **Physics cross-check (validation case `observer_ke_matches_builtin`):** in
  `examples/argon.lattice` plus an observer law `0.5 * a.mass * |a.velocity|²`, the `sum`
  row equals the built-in `atoms.kinetic_energy` at every sample. The comparison is
  bit-for-bit if the built-in sums the same terms in the same order, and the builder
  checks which. Otherwise the bound is derived from the summation order (n·ε·Σ|terms|),
  not tuned.
- **Cadence:** two law observers at `every 0.1` and `every 0.3` record 3:1 sample counts,
  and the slower one's rows sit at the expected times.
- **Thread-count identity:** the existing case is extended so that law-observer rows are
  identical on 1, 2, 3 and 8 threads.
- **Non-finite:** an observer `ln(a.position.x)` with an atom at negative x halts the run
  with `E0950`, pointing at `ln`, with the operand printed.
- **Panic isolation:** a test observer that panics on its third call gives `E0951`. The run
  completes, other rows are unchanged bit for bit compared with a run without it, and the
  observer's rows stop after call 2.
- **Contract audit:** `add_observer` refuses an empty `limitations`, an unknown `reads`
  name, and empty `outputs`.
- **Plugin (validation case `plugin_vacf_ideal_gas`):** `plugins/vacf` builds with
  `cargo build --manifest-path plugins/vacf/Cargo.toml`. Run on a force-free gas under a
  Langevin thermostat with friction γ, `C(τ)` matches `exp(−γτ)`. The tolerance is derived
  from the sample count, as the standard error of an average over N·origins
  (√(2/(N·M)) at lag 0, which widens with τ), and it is stated in the case, not tuned.
- **Artifact:** the round-trip test covers `series`, and the schema version is asserted.
- `cargo test --workspace --all-features`, clippy with `-D warnings`, `lattice validate`
  (with `--features gpu`), and the plugin build all pass.
